# Performance baseline

Dated observations for #36, not targets or promises. The original reading is
retained below with its invalid apply rows withdrawn. The corrected readings
measure the C integration and the subsequent passage-safety integration on
2026-09-08. No Rust code was changed for this measurement work.

Run `./docs/performance/measure.sh`, then
`./docs/performance/measure.sh --scaling`, sequentially on macOS. Each run
builds with `--release --locked` in a new temporary target directory, reports
its source status and hashes, and prints the actual command arguments before
each measurement. BSD `/usr/bin/time -l` supplies wall seconds and peak RSS;
the child process's stderr is captured separately. Any measured command failure
prints its stderr and stops the run, including in scaling mode.

An apply row is emitted only after its output exists and `mid info --json` can
read it. A play row requires a fresh invocation marker written by the fake
synthesiser after it reads the prepared MIDI file. Validation and building are
outside the timed command. The fake does not render audio or verify audibility.

## The two workloads

**Sparse** is `fixtures/olivia.mid` — 365 bytes, three tracks, 36 notes, no
control changes. It is already the reference Take, so nothing new is committed
for it and nothing about it can drift away from what the tests use.

**Dense** is generated by `dense-take.py`, deterministically: 200 Bars of 4/4
at 480 PPQ, four voice tracks, 6,400 notes, and 25,600 control changes — one
CC11 every 60 Ticks (a demisemiquaver) on every voice track, on a curve that reverses, because
a reading built for a monotone rise is a reading that has not met a fader. The
file is 150 kB and its only content is repetition, so the recipe is committed
and the file is not. `measure.sh` prints its SHA-256, and two runs on two
machines produce the same bytes. The script explicitly sets every generator
dial; ambient `DENSE_*` variables cannot silently change these workloads.

The proportions are the point: **four control changes for every note.** That is
what a densely automated DAW export looks like, and both `inspect` and `diff`
walk every one of them to answer a question about what is in force.

### Historical source diagnosis

The following diagnosis described the old code, not the C integration:

- **`diff::controller_differences` → `held`** (`src/diff.rs`). For each
  `(channel, controller)` pair the moments compared are every Tick either Take
  says anything at, and `held` answers each one by filtering the whole
  statement list from the start. One statement per moment, one full scan per
  answer: O(*statements*²) per pair. `program_differences` → `in_force` has the
  same shape and does not matter, because a Take states a handful of Programs
  and tens of thousands of control changes.
- **`Take::unranked`** (`src/unranked.rs`). `for state in &stated { for other
  in &stated { … } }`, plus a `found.contains` inside. O(*statements*²) again,
  and it runs on every `inspect` whether or not anything is unranked.

The old `held`/`in_force` helpers are no longer the current diff implementation.
The nested statement comparisons in `Take::unranked` remain. A current scaling
observation can identify a symptom; it does not independently profile its cause.

### Measurement failure checks

The original invalid no-op was reproduced before repair. Isolated executable
checks then ran the corrected script with temporary command shims, outside the
measured runs: build failure, inspect failure, apply failure, scaling diff
failure, successful apply with missing output, successful apply with corrupt
output, and successful play without invoking the fake synthesiser all stopped
without emitting a success row for that path. Nonzero command statuses and
stderr were preserved. A successful run whose child stderr contained a fake
timing line did not contaminate the measured values. Paths containing spaces
and apostrophes retained their argument boundaries, and temporary files were
removed after both success and failure. Shell syntax and whitespace checks
passed. These checks validate the measuring script; they are not additional
performance observations or an external-corpus acceptance.
